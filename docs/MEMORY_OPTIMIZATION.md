# 内存优化记录

2026-10-12，对 Go 服务的存储快照、一言和诗词接口进行优化。

## 改动

- 本地 JSON 存储直接复制可变结构，共享不可变字符串，避免每次读写都序列化并解析完整状态。
  嵌套标签、签到地址、歌单 JSON 等仍独立复制；Bing 的动态 JSON 仍按原有方式深拷贝。
  保留读快照隔离、更新失败回滚及原子文件替换。MySQL 实现未改变。
- 一言使用原始 JSON 和 ID/类型索引，替代每条记录的动态 map；原 Go 接口与 application 接口共享默认语料。
  原 Go 接口按类别加载，只解析最终选中的一条记录；application 接口仍在首次请求时加载全部类别。
  类型随机选择不再创建临时筛选切片，保留等概率抽样。
- 内嵌诗词仅解析一次，保留原始字段、额外字段及 null。旧版一言/诗词接口仍保持 omitempty 响应格式。

一言文件首次成功加载后缓存在进程中，修改 `yiyan/*.json` 后需要重启服务。
单类别加载失败不会缓存失败结果，文件恢复后可以重试；application 全库加载错误仍保持原有的进程内缓存行为。

## 本地测量

Windows amd64，Go 1.27.1，Ryzen 5 2500U；使用仓库内相同语料，单次基准持续 500 ms。
以下为每次操作的分配量（十进制 MB/KB），不是整个进程的常驻内存。

| 场景 | 改动前 | 改动后 | 分配减少 |
| --- | ---: | ---: | ---: |
| 本地存储读取，1 万条签到记录、2000 条 hosts | 9.34 MB | 0.813 MB | 91% |
| application 首次加载全部一言 | 12.74 MB | 6.67 MB | 48% |
| application 按类型随机一言，缓存预热后 | 38.9 KB | 8.9 KB | 77% |
| 原 Go 一言接口，固定 d 类别、缓存预热后 | 1.41 MB | 2.7 KB | 99.8% |

另在独立进程内，对全库加载前后分别执行 GC，再读取 `runtime.MemStats.HeapAlloc` 的差值：
旧 map 缓存约 6.91 MB，新默认共享缓存约 3.40 MB，保留堆内存减少约 51%。
这项测量包含新实现的全部类别及全库索引，不代表整个服务的 RSS 降幅。

基准入口保留在测试中，可复测当前实现：

```shell
go test ./internal/store ./internal/application ./api -run '^$' -bench 'Benchmark(FileView|QuoteLoad|QuoteRandomType|YiYan)$' -benchmem
```

## 验证及范围

- `go test ./...`、`go vet ./...`、`go build`。
- 覆盖嵌套快照修改与失败回滚、JSON 一致性、非法动态数据、并发语料加载、分类/全库共享数据、失败重试及接口 null/额外字段兼容。
- 未改变业务历史数据保留策略；长期积累的签到、Bing 档案仍会增长。
- 未采集线上流量或生产 RSS；实际效果取决于数据规模、请求类型、并发和 Go GC 配置。
